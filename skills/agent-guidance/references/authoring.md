# Author executable guidance

Load when writing an instruction body or context pointer. The document is for a named consumer under real permissions, not a narrative about a past session.

## Condition-bearing pointers

A pointer names out-of-context material **and the observable branch that should reach it**. Put the distinctive leading trigger first and collapse synonyms for the same branch. Example: “When a correction and prior findings are supplied, read the fix-review reference before dispositioning them.” A bare “see review docs” hides the branch; an always-loaded paragraph reproducing the entire review procedure spends attention on unrelated turns.

Give an exact local relative target or enabled `skill://<name>/<relative-path>` target, replacing the placeholders with the actual owner and asset. Do not make a pointer an unconditional autoload of every reference. A missing material target blocks that dependent claim/action; disabled suite files are not automatically reloaded by path fallback. Shared references remain callable plain material, not imaginary runtime invocations.

## Information hierarchy

1. Put what every branch must do in the core, in execution order.
2. Keep immediately needed definitions/rules beside the step they govern.
3. Move a branch's detail into disclosed references reached by explicit conditions.

Co-locate a concept's definition, constraints and caveats. A long but unique document can still bury the decision; split by actual branch or sequence, not arbitrary length. A sequence split earns its place when later steps demonstrably pull attention away from a hard current completion criterion. Moving text to another heading does not create a real context boundary.

When authoring or merging an OMP skill, read the picker-description and provenance convention in `skill://agent-guidance/references/omp-skill-contract.md`; that contract owns the exact rules.

## Ordered steps and observable bounds

Each step states an action, required evidence and the condition that tells the actor it is finished. Replace “understand the task” with a contract such as “identify every material acceptance criterion, its source, affected consumer and missing facts.” Later “implement” text must not let the actor skip unknown requirements or approval.

Define expected outputs concretely. A wrong-shaped output needs a positive ordered recipe; an omitted element needs a required slot; a conditional branch needs an observable predicate. A known rule violation under pressure needs a firm permission/invariant boundary with the intended permitted alternative. Do not add a long prohibition list to every writing problem.

Use compact meaningful terms only when the intended behavior is defined or already unambiguous in context. “Red-capable” is useful because its test can catch the named bug; “be thorough” alone is not a completion condition. Preserve hard safety/approval rules even if ordinary writing could phrase them more positively.

## One owner and pruning

For every rule, identify its maintained owner. Keep one normative expression and route other procedures to it. Retire conflicting duplicates within scope; do not keep a compatibility paragraph that continues competing behavior. Co-location joins fragments of one concept; duplication copies its meaning elsewhere.

The environment is also an owner: current manifests, directory layout and public help answer mutable tool facts. Cache only durable non-discoverable conventions, rationale and gotchas, and label evidence/status honestly. Review each sentence for stale assumptions, irrelevant exposition and no-ops. A disputed no-op is a behavior question for authorized assessment, not proof from the author's confidence.

## Source review output

Record the actual consumer and invocation, permission boundary, core sequence/done criteria, each disclosed target and condition, ownership resolution, changes and missing source facts. Do not claim this review demonstrates actual agent behavior, registration or runtime enforcement. That distinct authorized branch uses [behavioral assessment](behavioral-assessment.md).
