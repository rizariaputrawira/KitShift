# Sources and provenance

Independently authored read-only Git reporting procedure; no external skill text or code copied. Git state claims require observed repository evidence and an explicit scope/baseline. No tag, tracking, release, or changelog convention is assumed.

## Local maintenance

Read-only status inspection uses `git --no-optional-locks status` rather than plain `git status`, preventing its optional index refresh. This aligns the helper with the existing commit-message owner's read-only Git convention without changing comparison baselines, publication/release distinctions, or fetch authority. The procedure remains guidance, not OS enforcement.
