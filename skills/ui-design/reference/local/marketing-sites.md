# Design Taste: selective marketing-site complement

Use for a landing page, portfolio, or marketing-site redesign when the request benefits from audience-, brand-, and content-led composition. [Workflow and authority](../../SKILL.md#workflow-and-authority) owns ordinary native work versus explicitly selected persistent helper workflows. This reference adds selective marketing-site perspective; it requires no helper readiness/setup/state and grants no authority beyond the request.

Not the route for dashboards, data-heavy product surfaces, or multi-step application UI. A dashboard request is an explicit negative trigger: do not apply landing-page or portfolio prescriptions. Use the relevant product/UI owner instead.

## Route by request

1. Read the brief, relevant incumbent pages/components, brand/design guidance, available assets, and actual project stack. Treat user constraints, factual accuracy, accessibility, and the existing product identity as binding. Do not assume a framework, dependency, font, image, or content source.
2. Establish the page's audience, purpose, content hierarchy, and requested degree of change. Preserve existing identity and working behavior unless the user asks to change them. Ask one focused question only when unresolved ambiguity would materially alter the result.
3. Select only the reference(s) needed for this task:
   - [`landing-and-portfolio.md`](marketing-sites/landing-and-portfolio.md) for brief-led composition and content/assets.
   - [`redesign.md`](marketing-sites/redesign.md) for upgrading an existing marketing surface and checking its routes, metadata, navigation, analytics, and functions.
   - [`style-directions.md`](marketing-sites/style-directions.md) only when the brief or established brand calls for one of its named directions.
   - [`scroll-storytelling.md`](marketing-sites/scroll-storytelling.md) only when purposeful scroll-linked storytelling fits the request.
4. Implement within the authorized scope and installed stack, preserving functional controls and accessibility. Do not add a dependency or external service without the required authorization. A missing requested asset/tool is a prerequisite to report, not permission to fabricate a substitute.
5. Inspect the actual changed surface at relevant viewports when implementation and inspection are available. Report only checks actually performed; do not claim visual or runtime proof from source reading alone.

References are independent and lazy-loaded, not a mandatory stack. Do not use generic hero/section formulas, fabricated facts or assets, forced imagery or animation, random style selection, or overflow clipping as a way to conceal layout defects. Low-level motion implementation belongs to `ui-web-motion` build guidance; this reference family does not create a separate motion implementation owner.
