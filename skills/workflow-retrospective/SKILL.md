# Retrospective

1. Identify the named session/slice and available plan, implementation, actual check/review results and user acceptance evidence. Read only relevant permitted sources. If evidence is unavailable, state the exact missing basis rather than invent recurring failures, costs or tool behavior.
2. Load [learning extraction](references/learning-extraction.md). Separate decisions, lessons, candidate patterns and surprises, each with source evidence, applicability and promotion/revisit condition. A single observation is not a demonstrated recurring pattern.
3. Rank concrete friction and successful mechanisms by observed consequence: navigation, source ownership, approval clarity, checks, standards, instruction conflicts and tool use. Recommend the smallest verifiable change to the correct existing owner; no parallel ledger or invented organization-wide rule.
4. Report observed facts separately from hypotheses, unsupported claimed lessons and proposed improvements. Recommend rather than mutate documentation, skills, settings, memory services, requirements or policies unless that particular implementation is authorized. Consequential scope/security changes still need native approval; workflow-retrospective hindsight does not grant it.
5. Assess relevant categories supported by evidence: navigation/dependencies; automated checks (inspect current check/CI definitions before recommending a new guardrail); coding standards (prefer deterministic checks for mechanical issues and judgment guidance only for judgment); oversized global instructions; tool economy; ineffective instructions; and information access. Categories are prompts, not findings: do not claim missing guardrails without checking available configuration or recommend changes absent observed need.

**Done when:** recommendations are traceable to inspected evidence, limits and counterevidence are explicit, recurrence claims reflect actual repeated observations, and every suggested promotion names its owner, applicability and proving/revisit condition. No automatic graduation, new process engine, cost calibration or provider/model change.
