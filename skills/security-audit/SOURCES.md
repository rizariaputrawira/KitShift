All local procedures are modified adaptations. The explicit audit boundary, source/control depth, coverage gaps, challenge against strongest controls, meaningful boundary impact and smallest invariant-enforcing fix are retained. The current local revision cuts over copied custom security-orchestration assumptions to native OMP authority: the controller may inspect directly or delegate through actually available native source-review roles when allowed and useful. Separate discovery, candidate challenge and coverage reviewers are conditional on explicit requirements or concrete independence needs. Controller challenge is not independent review; unavailable required independence is reported as a limitation. Delegated reviewers never edit targets, execute, fetch targets or network resources, inspect credentials, install or delegate.

The shared docs-engineering security reference owns source-review procedure, evidence/finding decisions, delegation/challenge, reporting/assurance and separately authorized runtime evidence. Native role/result schemas and requested output formats govern representation, without custom record keys, exact arrays, strict-mode prerequisites or identity receipts. Stable local candidate identifiers, substantive evidence, decisions, rejected disproof and unresolved accounting remain required. Complete evidence for a bounded source-visible consequence can confirm an issue without runtime exploitation. Decisive runtime/model/deployment facts remain needs-validation; unsupported guesses do not establish severity. Reports describe the evaluator/source/operation basis actually observed, not unproved exact-file provenance or sandbox guarantees.

Removed from the local workflow: universal six-phase engine; research/general role aliases; fixed four-agent reconnaissance and wave/profile/fleet/cost-budget machinery; report forest under home; new run database/JSON ledgers; scratch-file/artifact orchestration code and literal promotion engine; Node validators/report-schema dependency; forced local reproduction for every source confirmation; mandatory distinct fresh discovery/refutation/coverage actors; custom role-boundary extension and managed-definition fingerprints; strict task-mode/structured-output prerequisites; exact custom candidate/disposition fields and terminal receipts; shell commands, target executables, installs, automatic writes/commits/provider directives. These removals do not relax evidence or runtime safety: only a separately authorized executor with demonstrated OS containment, dummy data, no real credentials/home state, no external/shared network (isolated loopback only if required), read-only target/toolchain, confined writes and resource/time limits may supply runtime evidence. Missing prerequisites leave the review source-only and runtime evidence unverified.

Only the seven listed companion/reference texts and core SKILL are adapted. Other upstream native/web/client/cloud/protocol/data/mobile companion bodies and scripts are not redistributed or linked as if installed. Their real trust boundaries remain eligible under the selected ordinary source-tracing mechanism; unavailable specialist facts are coverage gaps, not blanket safety assumptions. Cross-links to intake/change review load each owner rather than duplicate procedures/notices. No source claim asserts a deployed exploit, sandbox guarantee, whole-codebase completion or installed OMP compatibility. This local guidance revision was authored without executing targets, actors or runtime checks; source attribution, pinned upstream revision and the full license notice are unchanged.
